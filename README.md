# 片场 · Video Workbench

**从文章到成片的本机视频制作工作台，基于 Codex、Qwen TTS、HyperFrames 与 FFmpeg。**

状态：早期开发 · 使用场景：本机单人 · 已验证环境：macOS

片场面向本机单人制作，覆盖**营销视频**和**教学自媒体**。你提供文章与目标，Codex 负责拆解内容、编写脚本和维护工程，本地 Qwen TTS 生成旁白，HyperFrames 制作画面，FFmpeg 检查最终文件。浏览器工作台负责组织任务、展示实时日志、播放版本和记录确认。

整个项目采用 **一套公共制作流程、两个内容分支、一组可复用模板**。它支持逐阶段自动化，但不是无需判断的一键成片工具。

## 功能特性

- **从文章开始**：上传 Markdown 或 TXT，整理选题、标题、开场、口播、证据、案例参考和分镜草案，不要求先准备脚本。
- **按案例制作**：记录具体参考帧和借鉴方法，先做动态小样，再将认可的视觉方向应用到整片。
- **管理声音与字幕**：本地 Qwen 分段配音、试听、发音文本调整，支持转录和 SRT 导入校正。
- **查看执行过程**：展示实际任务日志、当前状态、阻塞原因及重试入口。
- **按版本审核**：播放不同版本、记录时间点意见；确认绑定文件版本，修改后提示相关检查失效。
- **验收与交付**：检查编码、尺寸、帧率、响度和峰值，生成抽帧、文件哈希及含可编辑工程的交付包。

营销分支围绕“问题 → 操作 → 成果证据 → 行动入口”；教学分支围绕“问题或成果 → 解释 → 跟做或判断 → 自检”，补充前置材料、练习和答案。

## 快速开始

### 环境要求

当前真实联调环境为 macOS。启动与 Worker 使用 POSIX 文件锁、进程组等机制，Windows 原生运行尚未验证。

| 依赖 | 用途 |
|---|---|
| Python 3.11+ | FastAPI 后端与独立 Worker |
| Node.js 22+、npm | 前端构建与 HyperFrames |
| FFmpeg、ffprobe | 音视频处理与交付检查，需在 PATH 中可用 |
| 已安装并登录的 Codex CLI | 后台执行内容和工程阶段任务 |
| 本地 Qwen 服务 | 有旁白项目的语音生成，需另行部署 |
| HyperFrames 相关 Skills | 制作 Agent 读取画面实现规则，需在本机可用 |

安装脚本安装 Python 和 npm 项目依赖，**不安装 Qwen 模型、Codex CLI、FFmpeg 或全局 Skills**。HyperFrames CLI 版本由仓库锁定；本项目五个视频 Skills 在 `.agents/skills/` 中维护。

### 安装与启动

```bash
git clone https://github.com/liuqing0224/video-workbench.git
cd video-workbench
./scripts/setup.sh
.venv/bin/python scripts/manage.py start
```

打开 [http://127.0.0.1:8794](http://127.0.0.1:8794)，进入“服务设置”，检查 Codex、Qwen、HyperFrames、FFmpeg 和 ffprobe 的探测结果。

当前 Qwen 适配器使用已联调的 `/health`、`/synthesize` 接口，转录通过 `/transcribe` 接入；**不假定任意 Qwen 服务都兼容此协议**。接口不同需要调整适配器。没有可用 Qwen 时，可以导入已有音频或制作无旁白版本，不会自动改用云端语音。

停止服务：

```bash
.venv/bin/python scripts/manage.py stop
```

默认只监听 `127.0.0.1`，前端由同一后端提供。API 和 Worker 日志分别保存在 `workspace/api.log`、`workspace/worker.log`。更多配置见 [运行手册](docs/运行手册.md)。

## 使用方法

在首页点击“上传文档并解析”，或通过“上传文档 / 新建视频”入口开始。选择营销或教学，补充目标、渠道、时长和不能公开的内容，然后按工作台六个步骤推进。

| 工作台步骤 | 平台产出 | 你需要检查 |
|---|---|---|
| 1. 内容方向 | 文章拆解、主题、标题、口播及证据 | 是否准确，是否只讲清一个核心问题 |
| 2. 案例与分镜 | 参考映射、镜头安排、视觉规范 | 案例是否适合，画面是否能支撑表达 |
| 3. 关键小样 | 实际动态片段、候选设计 | 观看小样并选择配色、排版和动效方向 |
| 4. 声音与字幕 | 正式声音、校正字幕、统一时间表 | 发音、停顿、阅读时间和字幕同步 |
| 5. 整片预览 | 完整工程与可播放预览 | 内容、画面、声音和镜间连贯性 |
| 6. 验收交付 | 最终 MP4、QA、抽帧、哈希与交付包 | 技术结果、对应版本与交付范围 |

界面六步对应底层八阶段：目标与证据、内容设计、镜头设计、关键小样、素材与时间锁定、整片制作、渲染验收、交付复盘。前两阶段合并为“内容方向”，最后两阶段合并为“验收交付”。

正式渲染前，在交付配置中明确分辨率、帧率和编码；有音轨时配置响度与真峰值目标。缺少检查目标不会自动判定通过。横竖版需分别适配和验收。

### 先确认视觉，再扩展整片

工作台的界面主题与视频配色相互独立。新片没有品牌约束时，不继承上一个项目的颜色，也不按“营销必深色、教学必浅色”套模板。

新建 UI 项目默认要求视觉确认。在“预览与确认”中观看实际动态小样，再选择方向。选择记录绑定设计、参考、小样及其证据的指纹；依赖文件变化后需要重新确认。技术 QA 不能替代用户的审美选择，小样选择也不代表完整视频或发布已获批准。

详见 [视觉方向确认](docs/视觉方向确认.md)。

### 修改后怎样继续

- 旁白变化：重新生成相关声音，校正字幕、时间与场景。
- 纯视觉变化：未变的声音和定时可继续使用，整片预览与最终 QA 需要重做。
- 重新编码或混音：针对新文件重新检查，旧哈希和 QA 不再证明新版本。
- 任务失败或阻塞：先查看实时日志和原因，再按当前输入重试。运行期间需要改输入时，先等待或取消任务。

旧产物和确认记录保留为历史。平台检查前置条件，不会把任务失败、残留文件或自动化判断当作人工确认。

## 技术架构

```text
浏览器工作台（React / TypeScript / Vite）
                  ↓
本机 API（FastAPI）── SQLite：任务、事件、版本、确认
                  ↓
独立 Python Worker（单实例、串行制作任务）
    ├── Codex exec：文章拆解、脚本、分镜与工程
    ├── Qwen / 转录适配器：声音与字幕材料
    ├── HyperFrames：检查、预览与渲染
    └── FFmpeg / ffprobe：最终文件验收
                  ↓
本地项目文件、运行副本与交付包
```

Markdown / JSON 是内容与交接依据；SQLite 是调度和确认依据。Codex 在独立运行副本工作，Worker 校验文件后登记产物。事件通过 SSE 更新，`STATUS.md` 用于汇总项目实施状态，不代替数据库中的任务记录。

### Agent 与 Skills

[AGENTS.md](AGENTS.md) 定义公共执行规则；项目专属文件记录本条视频约束。平台使用以下项目 Skills，不修改全局 Skills：

| Skill | 职责 |
|---|---|
| [video-orchestrator](.agents/skills/video-orchestrator/SKILL.md) | 阶段组织、输入检查与修改影响 |
| [video-marketing](.agents/skills/video-marketing/SKILL.md) | 营销脚本、收益证据与行动入口 |
| [video-teaching](.agents/skills/video-teaching/SKILL.md) | 教学选题、解释、跟做与自检 |
| [video-qwen-narration](.agents/skills/video-qwen-narration/SKILL.md) | 本地配音、发音文本与时间关联 |
| [video-delivery-qa](.agents/skills/video-delivery-qa/SKILL.md) | 技术检查、分支验收与可追溯交付 |

画面制作沿用已有 `hyperframes` 入口和领域 Skills。具体执行契约见 [技术架构](docs/技术架构.md) 与 [文件交接约定](文件交接约定.md)。

## 验证与已知限制

截至 2026-09-18，已完成以下实际验证：

- **真实文章制作闭环**：通过内置浏览器完成创建、导入、拆解、小样、Qwen 配音、整片预览、导出、技术复检、授权自动化确认、打包与下载。过程包含故障恢复，不等同于无人干预的一键生成。[完整测试报告](qa/e2e-full-video/REPORT.md)
- **视觉方向修订**：两组动态小样经用户选择后，将中性深灰与浅紫应用到四镜整片；新视频 32.13 秒、1080p／30fps，10 项技术检查通过，浏览器完整播放验证通过。[视觉修复报告](qa/visual-direction/REPORT.md)
- **平台回归**：38 项 Python 测试及前端 TypeScript / 生产构建通过，覆盖版本失效、视觉确认、路径边界、任务状态等场景。[当前项目状态](STATUS.md)

仍需注意：

- 自动化技术验收不代表用户本人已试听、认可完整成片，也不证明营销转化或学习效果。
- 配置与部分素材变化的依赖判定仍较保守，历史上游阶段可能显示失效；不能将所有提示简单清除为“通过”。
- 转录服务未返回可靠词级时间时，只使用真实段界或人工校正字幕，不宣称精确词级对齐。
- 当前不包含多人账号、公网部署、拖拽时间轴编辑器、自动发布或付费投放。公开发布需要单独授权。
- 模板填写示例包含演示材料，不代表已验证的产品事实。Qwen 的服务维护和接口兼容需在本机处理。

## 常见问题

**需要提前准备脚本吗？**

不需要。上传 Markdown 或 TXT 文章，由内容阶段整理选题、口播与分镜草案，再审核修改。

**能直接接入已有的 Qwen 服务吗？**

取决于接口是否匹配。当前适配器使用本机已联调协议，具体要求见 [运行手册](docs/运行手册.md#工具与配置)。平台不会自动部署模型或切换到云端声音。

**为什么修改后需要重新确认？**

确认针对具体输入与文件版本。修改导致依赖变化时，相关预览或 QA 失效；历史记录保留。只有未受影响的确认可以沿用。

**克隆仓库后，为什么没有历史视频？**

`workspace/` 不纳入 Git，其中包含数据库、个人素材、音频、视频与运行记录。克隆只获取代码、规则、模板和报告。历史项目通过 [备份与恢复](docs/运行手册.md#备份与恢复) 迁移。

**可以部署到公网或自动发布吗？**

当前仅支持本机工作流，不包含多人账号或公网部署方案。制作交付与公开发布分开，发布和投放需要单独授权。

## 反馈与贡献

可通过仓库 [Issues](https://github.com/liuqing0224/video-workbench/issues) 提交问题或功能建议；需具备仓库访问权限。报告问题时，请提供：

- 操作系统、Python / Node.js 与相关工具版本。
- 复现步骤、预期结果、实际结果和所在制作阶段。
- 脱敏后的日志、截图或最小复现材料。不要提交令牌、私人文章、数据库或用户素材。

提交代码前：

1. 阅读 [AGENTS.md](AGENTS.md) 和 [技术架构](docs/技术架构.md)。
2. 在独立分支修改，使用测试项目或临时目录，避免影响正式视频资产。
3. 为行为变化补充必要测试，执行上面的测试与构建命令。
4. 提交 Pull Request，说明问题、改动、验证结果及已知限制；同步更新相关文档。

文档、案例方法和错误报告同样欢迎。项目暂未单独提供 `CONTRIBUTING.md`，当前贡献说明以本节为准。
