## 所见结构

| 时间约 | 画面 | 作用 |
|---|---|---|
| 0–4 秒 | 紫色柔光背景，应用图标与名称出现 | 建立新产品识别 |
| 5–10 秒 | 应用全貌、工作区选择、输入区域近景 | 让观众快速认识使用入口 |
| 11–15 秒 | 模型/服务商菜单，旁侧短标题 | 把操作与一个卖点对应 |
| 16–22 秒 | 输入植物养护日历需求，执行界面与代码变化 | 提供具体任务片段 |
| 23–29 秒 | 导入会话、扩展、网页上下文等标题与界面片段 | 用一致格式组织次级能力 |
| 30–32.5 秒 | 应用标识、桌面端名称、平台信息与网站地址 | 让发布信息落到行动入口 |

## 设计解读

紫色背景保持连续，深色 UI 窗口是主要载体。全貌交代上下文，局部裁切强调操作；旁侧短标题承担解释职责，用户不必读完所有 UI 小字。结尾出现可见网址，比只有品牌标识更接近可执行的转化收尾。

值得复用的是“功能标题 + 对应界面证据”的双层结构。它允许多个功能共存，又保持统一排版和观看习惯。

## 适用与边界

适合 SaaS、桌面应用、开发工具与版本更新。功能数量较多，最后数项展示很短；若目标客户尚不了解产品，建议减少到一个主任务和两项辅助能力。不能把加速的演示过程当作真实等待时长。

## 用我们的生产线复用

优先做 30–45 秒版本：品牌 2–3 秒 → 核心任务 15–20 秒 → 两项辅助收益 6–10 秒 → 行动入口 3–5 秒，具体依照可读性调整。

资产：品牌背景、应用标识、界面状态、真实任务输入、成果/变化、最终入口。组件：UI 容器、焦点裁切、侧栏说明、标题卡、CTA。

本地 Qwen 提供连贯解释，HyperFrames 用同一时间表同步标题、控件与字幕。先锁定 8–12 秒“卖点标题 + 实际操作”小样。横竖版重排文字与界面位置，不直接裁掉窗口两侧。

验收：每句卖点对应可见操作或结果；核心控件易读；网址/入口正确；演示数据已处理；用户知道下一步去哪。
