# HyperFrames 案例：讲解逻辑、配色与动效经验库

日期：2026-09-17。用途：为营销片、教学自媒体和文章改编选择可验证的镜头方法。研究不是审美排名，也不代表模板已经适用于中文成片。

## 先纠正参考来源

用户指定入口：[案例画廊](https://hyperframes.app/zh/showcases)。实现核对：[HyperFrames 开源组件](https://github.com/heygen-com/hyperframes/tree/main/registry/blocks)。

通过 browser-control / Ego Lite 实际点击发现：标称“30秒 SaaS 产品宣传片（Linear 风格）”的卡片加载 `app-showcase.mp4`，播放器时长 **5.5秒**，实际是三手机展示。不能据此声称看过一条完整的30秒Linear式宣传片。此前的主参考选型降为待验证；下文按真实组件名区分。

证据分级：

- **画面观察**：本地直接渲染官方组件并查看连续采样图，覆盖 app-showcase、data-chart、ui-3d-reveal。它们是当前组件的输出，不自动等同于网站最终样片。
- **代码核对**：读取公开组件的颜色、布局和时间参数；源文件及哈希见 `source/retrieval.json`。源码默认色不一定等于画廊视频经过处理后的像素色。
- **网站观察**：实际播放入口、媒体地址和播放器元数据；见 `browser-inventory.json`（如某项加载失败，保留失败状态）。
- **设计推导**：下面的教学改编、用色比例和检查建议是本项目提炼，不冒称原片已经验证教学效果。

未听辨参考音轨，不评价其配乐质量、逐句配音或声画卡点。不以标题、封面或组件安装成功代替完整观看。

## 一、三类讲解任务，不用同一种镜头

| 观众的问题 | 推荐组织逻辑 | 画面需要证明什么 | 适用组件方法 |
|---|---|---|---|
| 这是什么、有什么用？ | 识别主体→展示一个能力→看到反馈→记住价值 | 产品与结果的对应 | app-showcase / ui-3d-reveal |
| 为什么会这样？ | 明确问题→建立比较尺度→依次展示证据→解释关系→指出边界 | 关联、差异或变化 | data-chart / 定性关系图 |
| 我该怎么做？ | 给出目标→指出位置→执行动作→显示结果→自检 | 操作确实导致预期反馈 | 清晰的平面界面＋局部聚焦 |

案例库里许多片段主要负责吸引注意或品牌记忆，并不是完整课程。把它们用于教学时，要补上前置条件、解释和自检；不能把短促特效串联当作讲课逻辑。

## 二、核心案例深拆

### A. app-showcase：先看见主体，再看见内部发生什么

[源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/app-showcase/app-showcase.html) · [连续采样图](app-showcase-frames/contact-sheet.jpg)

**实际结构**：中央手机先建立视觉焦点，左右手机从重叠位置展开；主体稳定后，中央进度环、活动条和右侧折线才更新，最后保持整体构图。源码阶段为0–2秒构建、2–4秒内部变化、4–5.5秒收束。采样图0.5、1.5、2.8、4.8秒可见这个过程。

**配色**：背景 `#F1F2EC` 与 `#E8ECDA`，深色手机面板 `#1A1A1A`，轮廓/深文字 `#271F15`，进度强调 `#E4FA72`，辅助文字 `#7C857C`。成功之处是外部明亮、内部深色，把对比集中到主体；黄绿色主要承担状态含义，不给每块信息分配一种颜色。

**动效逻辑**：移动主体建立层级，随后主体内的数据变化提供新信息。不是所有元素一起淡入，也不是每个数字都持续跳动。轻微整体推进保持活力，但用户的注意点仍在设备内部。

**教学迁移**：将“三台手机”换成“订单、履约、复购”三个有共同顾客标识的记录面板，保留中间主对象，围绕同一对象展开关系。不要无缘无故给桌面数据套手机外壳。

**不能直接照搬**：三块屏幕同时变化适合概览，不适合新手学习细小控件；原例右侧浅色图表细线对比偏弱，中文信息流要加粗并放大。模板的健身数据不属于Menza事实。

### B. data-chart：先给尺度，再给事实，最后给关系

[源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/data-chart/data-chart.html) · [连续采样图](data-chart-frames/contact-sheet.jpg)

**实际结构**：标题、单位与图例先出现；柱子逐项长出，完成后数值出现；另一条线沿数据点绘出，点与百分比随后跟进，最后出现来源。当前源码总时长15秒，不能使用画廊文案的12秒作为实际工程时长。

**关键时间**：柱子从1.5秒起按0.5秒错开，每根0.8秒；折线从4.5秒起用3秒绘出。采样图1秒仅建框架、4秒柱状展开、7秒折线推进、10秒后形成稳定读图状态。它是依次展示的双指标图，采样中没有排名重新排序，不应把“竞赛”标题当作bar-chart-race机制。

**配色与文字**：纸白 `#FAF9F6`，正文 `#333333`，柱子 `#5C5C5C`，折线及对应数值 `#326FA8`，辅助文字 `#666666`，网格 `#E8E8E8`。衬线标题建立编辑感，无衬线标签保持实用。中文应选实际可用的中文字体并重新检查字宽，不能只换字体名。

**讲解价值**：第一指标先让观众理解量级，第二指标再提出关系问题。用色稳定比颜色丰富重要；数字动画是呈现过程，不能捏造中间阶段的业务事实。

**风险**：双指标不同单位不能靠曲线高度制造因果印象。该例小字和来源在手机观看时偏小，需增加可读尺寸。Menza文章没有可信转化率或金额，不能直接套上此例数字；应迁移“先证据、后关系”的顺序，用定性记录关联。

### C. ui-3d-reveal：整体定位→局部聚焦→空间展示→品牌收束

[源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/ui-3d-reveal/ui-3d-reveal.html) · [连续采样图](ui-3d-reveal-frames/contact-sheet.jpg)

**核对到的结构**：0–1.35秒标识；1.5–3.4秒平面界面；3.5–4.8秒推进；4.2–5.55秒倾斜；5.55–7.3秒保持；7.3秒后退出；7.9–13秒品牌收尾。实际采样是Figma风格设计界面，并非Menza，也不能称为已验证的Linear实际产品片。

**配色**：画布/面板以 `#1E1E1E`、`#2C2C2C` 为主，正文 `#E8E8E8`，选择状态蓝 `#18A0FB`，其他鲜艳色来自品牌标识和界面内容。多色标识不等于全片应该使用多种强调色。

**动效价值**：先看平面才知道是什么，推进后知道看哪里，倾斜与阴影赋予物体感。视角变化只负责展示层级，不能证明功能已执行。

**教学迁移**：概览可倾斜，具体操作要回到正面、放大控件并展示反馈。品牌收尾对营销有用；教学更应把最后几秒留给总结或练习。大角度、强纵深和快速飞离会损害文字阅读，不用作全片默认姿态。

### D. vfx-magnetic：输入位置→邻近区域响应→恢复

[源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/vfx-magnetic/vfx-magnetic.html)，仅代码核对，未完成该组件渲染观察。

源码使用暗底 `#0C0C0C`、浅字 `#E8E8E8` 和蓝色 `#70C7ED`；用时间轴驱动模拟指针位置、作用强度和排斥状态，8秒附近短暂触发排斥。不能只凭名称断言当前源码已实现画廊描述的所有粒子效果。

可提炼的是局部反馈：指向哪里，哪里响应，结束后恢复。用于讲清关联对象比所有面板一起闪烁更有效。必须标记它是编排的演示状态，而不是观众可点击的真实交互；不把装饰场线叫作模型真实推理过程。

### E. vfx-portal / vfx-liquid-glass：注意力过渡，不是事实证明

[Portal源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/vfx-portal/vfx-portal.html) · [Glass源码](https://github.com/heygen-com/hyperframes/blob/main/registry/blocks/vfx-liquid-glass/vfx-liquid-glass.html)。仅代码核对。

Portal的时间轴在推进阶段增加能量和色散，随后降低干扰，进入稳定状态。可借鉴“变化峰值短，结果保持长”；观众应该最终看清结果，而不是只记住入口效果。

Glass源码背景 `#030407`、青 `#00D4FF` 与紫 `#A855F7` 的强调，以及用于反射的白色和暖色环境光。反射颜色不等于正文配色。当前源码含持续移动的模拟指针，不能把画廊文字所写的“最后完全干净”当作已观察事实。

用于教学时仅适合章节入口或概念隐喻。折射、模糊、色散不应覆盖关键操作文字；展示业务结论时必须回到稳定、无歧义的视图。不要从“炫酷效果”推导“教学有效”。

## 三、其余案例怎样使用

以下是用途判断，除另有上述证据外不声称已逐帧分析。

| 案例类型 | 可借鉴的表达任务 | 教学改编时的限制 |
|---|---|---|
| 飞行地图 | 始点→路径→终点，连续追踪同一个对象 | 只有内容含空间关系才用地图；数据流不是地理路线 |
| 手机＋电脑展示 | 同一任务在不同终端交接 | 需要真实的跨端任务与反馈，不只旋转设备 |
| 品牌混剪 | 用短促变化制造开场期待 | 不能承担复杂推理或跟做步骤 |
| 流体背景 | 给简单主视觉增加缓慢层次 | 字体与数据保持稳定，背景不争抢视线 |
| 玻璃碎裂 | 表达结束、替换或中断 | 不用在关键结论刚出现、尚未读完时 |
| 光标文字 | 将注意集中到一句核心问题 | 一次只强调一处，不整段发光 |
| Logo退场／极简揭幕 | 建立识别与结束记忆 | 不是完整教学结构；标题与实际媒体须核对 |
| 金额计数器 | 突出单个已证实的结果 | 没有金额来源就不能用；滚动数字不是事实依据 |
| 社交覆盖层 | 给正在讲述的内容补一条上下文证据 | 保留来源、避免遮挡主体，社交反应不等于权威证明 |
| 卡拉OK字幕 | 帮观众定位当前说到的位置 | 依赖真实对齐；没有词级时间只做句级 |
| 网站转视频 | 从全貌进入关键页面区域 | 真实截图作为证据，保留出处与版本，不能用转场替代功能演示 |

## 四、沉淀为可复用方法

### 1. 每镜只解决一个认知问题

先填写“观众在这一镜结束时，比开始时多知道什么”。若答案只是“看见一个标题”，检查是否应该并入另一镜。解释镜头需要对象、关系或状态变化，不是将旁白全文放到屏幕上。

### 2. 运动必须有作用

- 移入：引入对象；移近：建立比较；连线：表达有依据的关联。
- 放大：让关键细节可读；高亮：选择当前注意点；展开：提供证据。
- 淡化：降低已知背景的权重；保持：给观众时间阅读和判断。

检查办法：关掉这段动画后，是否更难理解？如果完全没有差别，它可能只是装饰。装饰可以有，但不能替代解释动作。

### 3. 配色用角色管理

定义背景、主体面、正文、辅助文字、证据强调、疑问/异常，分别说明用途。默认同一类信息沿用同一颜色，跨镜头保持身份。不要把一整套手机品牌色无理由套进数据教学。

从已有组件得到两个候选方向：

| 方向 | 背景 | 主体/正文 | 强调 | 适合任务 |
|---|---|---|---|---|
| 明亮产品展示 | `#F1F2EC` | `#1A1A1A` / `#271F15` | `#E4FA72`，主要放深色面板 | 产品识别、概览、结果展示 |
| 编辑式解释 | `#FAF9F6` | `#333333` / `#5C5C5C` | `#326FA8` | 数据关系、证据与概念讲解 |

这些是源码提取的候选，不是用户已确认的新片主题。黄绿放在浅背景上可能不够清楚，不能只因为颜色好看就用于小字。最终以真实中文画面和对比度检查为准。

### 4. 时长由理解任务决定

从案例学习顺序和缓急，不照搬秒数。复杂图先完成一个层级，再引入下一层；状态结果停留时间按实际阅读与旁白确定。先锁定真实声音后安排动作，不能机械按每镜27%、57%触发所有变化。

### 5. 连贯性依赖对象延续

相邻镜头尽量保留一个可辨认的对象、位置、颜色或运动方向。结尾的证据对象成为下一镜开头的问题对象。转场不必每次重新进标题，也不必每页插入空白。

### 6. 交互演示写成因果链

`观众要看什么 → 操作对象 → 动作 → 局部反馈 → 状态结果 → 如何核查`。

没有操作只是镜头运动，就写“镜头推进”，不要写成“用户点击后系统分析”。合成演示界面明确标注；真实业务能力必须另有依据。

### 7. 设计检查不靠赞美词

逐项检查：主体是否一眼找到；最终输出尺寸下字是否能读；颜色是否语义一致；变化是否与讲解同拍；镜头是否回答了问题；结论是否有证据；特效结束后是否有可读稳定态。出现问题先修关键小样，再扩展全片。

## 五、Menza 下一版的具体应用

暂定“明亮产品主体＋编辑式证据说明”为两个待比较的小样方向，不能把两套主题随意交替拼接。优先测试订单关联的一个完整步骤：

1. 给出唯一问题：“赠出去的到底是哪款小样？”
2. 订单记录出现，赠品字段显示“免费小样”；缺失信息成为视觉焦点。
3. 履约记录进入同一坐标体系，同一顾客/订单标识被高亮。
4. 两条记录完成对应，展开明确产品类型；保留来源身份。
5. 下一条购买记录加入，形成可追踪路径；画面说明“能够追踪”，不虚构转化数字。
6. 小样结束停在可读结果；后续再讨论“关联不等于因果”。

画面只放当前必要标签；完整解释交给旁白，字幕按实际句段拆分。先做8–12秒方向样片，真实声音较长则按理解需要调整，不能强行压缩。不会照搬Figma商标、健身数值或手机外壳；未拿到Menza真实UI时用明确标注的解释性示意。

## 六、复用时必须携带的证据

使用 `经验卡模板.md` 记录具体方法、输入要求、镜头状态、色彩角色、反例和小样证据。当前方法属于**已研究、待本项目应用验证**；只有真实小样通过且人工要求得到满足，才能升级为本项目已验证经验。播放量、审美认可和学习效果仍需独立反馈。
