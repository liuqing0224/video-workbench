# 视频视觉方向确认

2026-09-18。工作台配色与视频配色相互独立。无品牌约束时不复制上一项目配色；营销/教学是内容分支，不是固定深浅主题。

## 交接

内容方向记录品牌、气质和禁用风格；案例与分镜列具体参考帧/时间点、证据等级、颜色角色、比例及借鉴边界；关键小样产出真实动态MP4。用户在“预览与确认 → 先选视觉方向”播放比较，勾选已看过后选择一组。该选择只批准小样视觉，不批准完整视频、声音或发布。

```json
{
  "candidates": [
    {
      "id": "light-v1",
      "name": "浅色编辑式",
      "description": "纸白底、蓝紫当前对象、琥珀旧报告",
      "reference": "data-chart 7秒与10秒采样；借鉴信息顺序和留白，色值为本次推导",
      "design_path": "documents/visual/light-v1.md",
      "sample_path": "assets/visual/light-v1/sample.mp4",
      "evidence_paths": ["assets/visual/light-v1/index.html", "assets/visual/data-chart-reference.jpg"]
    }
  ]
}
```

通过平台 sample 阶段制作时，Worker在实际检查和渲染成功后自动归档工程、设计、参考与MP4，并追加候选清单。Agent可在documents/VISUAL-CANDIDATE.json提供name/description/reference，不填写虚假的确认状态。下面的手工清单用于已有真实小样导入。

保存为项目 `documents/VISUAL-PLAN.json`。每个候选有唯一ID，最多8个；路径必须在本项目内且无符号链接。准备完成才发布清单，不能把空文件当小样。任何素材、HTML等依赖应列入evidence_paths。参考可以借鉴布局与动作，不需照抄颜色；原创选择应明确标注。

SQLite的`visual_reviews`保存candidate_id、指纹、actor(user/automation)、decision、note及时间。指纹覆盖计划、公共DESIGN/REFERENCES、候选设计、小样及所列证据。最新用户决定覆盖旧选择；重新修改或文件缺失会失效。自动化通过不会变成用户认可，且不会覆盖有效用户选择。此为本机单用户显式主体标记，不是多用户身份认证；Agent不得以user冒充审美选择。

## 平台约束

UI新建项目默认visual_review_required=true；老项目保持原行为，新增VISUAL-PLAN.json即可进入视觉修订。已要求视觉确认但缺少计划或有效用户选择时，整片preview、render、article完整自动生产和package禁止启动。入队与Worker执行时均复核；已有视频的独立qa仍可测量，但不能凭QA绕过打包视觉门禁。新门禁不撤销旧视频的历史审批，未生成新片时不能称旧视频已经修复。

纯视觉修改保留audio/captions、SCRIPT、BRIEF、voice-config、timing和claims未变的正式时间依据；预览/渲染仍按完整输入指纹重新检查。配置变更仍保守失效，未在此次拆分成全部细粒度依赖。

- GET `/api/projects/{pid}/visual`：候选、有效选择、历史。
- POST `/api/projects/{pid}/visual/review`：候选ID、读取时指纹、actor、decision、note；过期拒绝。
- GET `/api/projects/{pid}/visual/{candidate_id}/sample?fingerprint=...`：只返回清单中的当前MP4，不执行HTML。

制作Agent从平台传入的当前选择读取对应design_path，保持共享颜色语义。整片仍须逐镜核对实际画面、字幕、安全区与转场，并在最终编码后生成QA/抽帧/哈希。人工音色自然度和内容效果不能由视觉确认代替。
